One rule (Jira + GitHub must match)

Parent = Domain epic. Capability = label. Never two parents.

QuestionAnswer
Where does code go?domains/<domain>/src/ — never modules/, never capabilities/
Which Jira parent for delivery work?Domain epic (e.g. Domain: Product — UIFPE-51)
How do I tag capability standards?Labels: capability:api, capability:schema, etc.
When is Foundation Epic the parent?Pre-domain platform work only (registry stand-up, CI template, CD skeleton)

Worked example (product API): parent UIFPE-51, labels domain:product + capability:api, code in domains/product/src/api/.

Jira Automation (required — one-time admin setup)

Smart Commits and branch/PR workflow move UIFPE issues through statuses, but a status change alone does not notify anyone. A Jira project admin must configure these automation rules once in UIFPE → Project settings → Automation:

When issue transitions toAction (required)
Code ReviewAssign to and/or comment-mention the PR reviewer(s) — turns “PR ready” into an actual notification
Ready for QAAssign to and/or comment-mention the domain’s QE Lead — turns “merged / ready for test” into an actual notification

Without these rules, reviewers and QE must poll the board; the Git ↔ Jira integration is incomplete. Full context: Notifying QE and reviewers in jira-github-integration.md.
