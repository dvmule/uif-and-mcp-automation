# Patterns

## What this is

Reusable solution patterns — the recurring shapes a domain team composes from rather than reinventing. A pattern earns a place here only after it has proven itself across more than one domain or capability; a one-off stays in the domain that needs it.

## What a pattern document contains

- The problem it solves and the forces in tension.
- The shape of the solution, described portably (not tied to one vendor unless UIF mandates that tool).
- Which capabilities it spans and what an FDE decides locally versus what must conform.
- Its security posture and the observability signals it emits — inputs to the design, not an afterthought.

## Governance

Central. Add a pattern here when the third repetition appears — not in anticipation of one.
