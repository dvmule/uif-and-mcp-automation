# Gold Schema: Product v1

Master schema for the Product entity in the Gold layer.

## v1 reset — 2026-06-01

The schema was reset from a wide 15-column framework-validation shape to a **lean 5-column** shape focused on identifiers. This was a **breaking change** vs. the prior published artifacts (`product.gold-{event,message,api}-value` v1) — column set, PK definition, and `product_id` semantics all changed.

| Field | Source | Notes |
|---|---|---|
| `inventory_item_id` (PK1) | `MTL_SYSTEM_ITEMS_B.INVENTORY_ITEM_ID` | EBS internal surrogate. New PK column. |
| `product_id` | `MTL_SYSTEM_ITEMS_B.SEGMENT1` | **Meaning changed** — previously this was `INVENTORY_ITEM_ID` as string. Now it's the human-readable item number (SEGMENT1). |
| `org_id` (PK2) | `MTL_SYSTEM_ITEMS_B.ORGANIZATION_ID` | |
| `isbn10` | `EGO_MTL_SY_ITEMS_EXT_B.C_EXT_ATTR6` where `attr_group_id=741` | Item-level (broadcasts across orgs). |
| `isbn13` | `EGO_MTL_SY_ITEMS_EXT_B.C_EXT_ATTR8` where `attr_group_id=741` | Item-level (broadcasts across orgs). |

**Dropped** in v1 reset: `item_number`, `status`, `description`, `item_type`, `primary_uom`, `bom_item_type`, `source_created_at`, `source_updated_at`, `translations`, `bom_components`, `extended_attributes`, `_gold_updated_at`, `_silver_max_updated_at`.

**New PK:** `(inventory_item_id, org_id)` — was `(product_id, org_id)` where `product_id` was `INVENTORY_ITEM_ID` cast to string.

Schema Registry re-publish is intentionally deferred until the 5-column shape is confirmed stable. The currently-published v1 artifacts are now stale until that step runs.

## Files

- `master.json` — JSON Schema Draft-07. Source of truth for the Product contract. Each property is tagged with `x-channels` declaring tier membership (`event` ⊂ `message` ⊂ `api`).
- This README.

## Tier subsets (generated by CI, published to Schema Registry)

| Tier | Schema Registry artifact | Attributes (current) |
|---|---|---|
| event | `product.gold-event-value` | `product_id`, `org_id`, `isbn10`, `isbn13` |
| message | `product.gold-message-value` | same as event (no message-only field in v1 lean) |
| api | `product.gold-api-value` | message ∪ `inventory_item_id` |

The subset hierarchy `event ⊂ message ⊂ api` is enforced by CI — any property in `event` must appear in `message`, and any in `message` must appear in `api`.

## Breaking-change policy

- Adding an optional property → minor version (`v1` stays).
- Removing or renaming a property, or changing required types → new major version (`v2`).
- Re-tiering a property (e.g. moving from `api` to `event`) → minor version. Consumers in the smaller tier are unaffected; consumers in the larger tier always saw the property.
